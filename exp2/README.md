# 实验 2：纯 IC —— 开发入口

这个目录是**实验 2 的冷启动包**，开发会话从这里开始读。

## 实验 2 是什么

一个由 IC（意图编译器）独自承担整个开发流程的系统：理解需求、派活、控制编码过程、验收、纠错。用它完成 dpipe 的 15 轮需求更新，与已经跑完的"SDD 单独执行"比较准确率和成本，而且要明显胜出。两组之间唯一的变量是"只有 IC 一方"还是"SDD 单独执行"，其余条件全部相同。

## 阅读顺序

1. `BACKGROUND.md`：之前的实验发生了什么，哪些做法被证明有效、哪些失败了，原因是什么。设计里每一条主张都从这里来。
2. `DESIGN.md`：设计草稿（已定、提议、未决都有标注）。
3. `DEV-GUIDELINES.md`：开发守则，尤其是"确定性交给代码，但规则不能写死"，以及离线验证怎么做。
4. `TARGET.md`：要超过的对照组成绩，以及成本口径。
5. `inputs/dpipe/`：15 轮原文（只有题面，没有测试和答案）。
6. `reference/UPDATE-TAXONOMY.md`：各轮更新类型的分析，供设计离线验证时参考（使用限制见守则）。

## 关于这个仓库

- 本分支 `exp2-pure-ic` 基于实验 1 最后一版代码（v8，`ic-sdd-v8-dev` 分支）。`main` 是很早期的设计，**不要读，也不要往那里合并**。
- `src/core/` 里有可以复用的模块：存储与事务（`sdd-compiler.ts` 的 store 部分）、原文切分与段落编号（`source-payload.ts`）、按对象分组交付全文（`sdd-grouped.ts`）、落地证据（`sdd-landing.ts`）、可执行样例与其运行（`sdd-executable.ts`、`experiments/sdd/example_runner.py`）、OpenCode 调用与结构化输出（`src/model/opencode-transport.ts`）。这些都是为"IC 配合 SDD"写的，纯 IC 里只拿可复用的部分，不要把 SDD 的阶段结构带进来。
- `experiments/sdd/` 是实验 1 的 SDD 适配和串行运行器。实验 2 不调用 SDD，只有运行器里的检查点、续跑、看门狗、成本统计这些思路可以参考。
- 项目根目录的 `AGENTS.md` 是长期工作规则，仍然适用；其中指向 `development/` 的那些文档，大多不在 git 里，读不到就跳过。

## 开发会话的边界

- 写代码和单元测试、做离线验证。不运行真实的模型串行，也不运行官方验证器：真实运行在本地进行。
- 不读、不要求、不反推官方测试或参考答案，本包里也没有这些。
- 设计上的疑问或需要改设计的地方，在提交说明或文档里写清楚，交回设计会话决定；不要自己扩大或缩小范围。
