# 审查员召回对官方失败（2026-10-25，零模型成本）

问题：验收模块的任务是"官方测试会挂的地方，审查员先报出来"。这个数以前没算过。本文件对四次运行（rep1j、rep1k 六轮；rep1l、rep1m 两轮）算它。

## 方法（代码规则，可重复）

- 官方侧：每轮**首次交付**提交的 verifier.log（official/round-NN/<首次交付 sha>/），取 status≠success 的用例，只用 case_id、requirement_ref、intent 三个字段（不读测试内容）。"轮末仍挂" = 同轮保留提交的 verifier.log 里仍 ≠ success。
- 审查侧：state.executions[].review_items 中该轮全部条目（三次审查合并，任何处置）。
- op = requirement_ref 最后一段（transform.window → window）。"op 被提到" = 该轮任一条目文本含该词（词边界）。"行为被提到" = 用例 intent 的词（去掉 op 词和停用词）与条目文本有交集。这是关键词规则，粗；行为级只当解释，op 级当证据。
- 为什么用首次交付：审查在修复之前，被修好的用例轮末不挂；对轮末挂的用例算召回会低估审查员。

## 读法

1. **看对了地方（证据，op 级）。** 早轮首次交付挂的 op，审查员提到 70–90%（4/5、6/7、9/11、13/17、10/14）。
2. **轮末剩下的，大多在审查员提到过的 op 里（证据）。** rep1l R2 轮末仍挂 115，其中 110 在被提到的 op（profile 54、compare 18、rollup 16、pivot 10、detect 8）。rep1m R2 仍挂 30，27 在被提到的 op。**丢分主要在"看见了没修好"，不在"没看见"。**
3. **固定盲区（证据，op 级；每条都在四次运行的某几轮里"轮末仍挂且 op 从未被提到"）：**
   - `derive` "Derive negative function edge cases"：四次运行、每一轮各 1 个用例，从未被任何条目提到。
   - `fill` "Fill constant"：rep1l、rep1m 两轮各 2 个，未提到。
   - `manifest` "BLAKE2b manifest""Manifest row count and size"：rep1j R5–R6 共 10 个、rep1k R5 5 个。R5 原文把哈希从 SHA-256 改成 BLAKE2b，审查员在 transform/verify 上看到了（守卫 G1、G8 翻转），**manifest 上没看**。这是"一个概念改多个命令"的横切变更在审查侧漏掉的实例。
   - `validate` 7 个（rep1k R5）：R4 原文没写 row 起算，执行方取了文件行号，审查员也没报——原文没写的东西审查员也不会报，这与之前的归因一致。
4. **看见了却没送出去（证据，一例）。** rep1j R5 三次审查都报了"transform 写了禁止的 .sha256 旁路文件"（V5.1.1、V5.2.1、V5.3.1），三条处置都是 logged，前提 value_not_stated ×3：formalizer 对"文件不应存在"写不出"期望值"，条目降为记录不送修。当轮 determinism 用例 "Transform SHA-256" 轮末仍挂。**这是验收侧自己的损失**，与 12j.3 的闸同类：一条只记录的前提把存在性检查当成没值。

## 对"验收做完了没有"的回答

- 看见：大体做到，盲区具体可数：横切变更（哈希改法影响 manifest）、从不报的 derive 边界、fill constant。
- 送出：有一个洞（value_not_stated 对存在性断言），已有一例造成丢分。
- 修好：是主要丢分处，不属于验收模块。

## 局限

关键词规则在行为级会漏（intent 用词与审查员用词不同），op 级可靠。只有四次运行，盲区的"固定"是四次里的固定。首次交付的 verifier.log 来自开发会话的打分流程，与轮末同一脚本。
