# 批 4：原文状态层与审查范围（DESIGN-DEEP §1–§2），2026-10-25

状态：设计会话起草，待用户审；审过后原样发开发会话（只写效果与验收，做法由开发定）。

## 一、这一层的逻辑（给人读的）

审查员和执行方只对放在它们面前的句子做事。四次运行证明了两件事：放得多（整对象视图）它们会顺带回看早轮命令，分高但包等于全文；放得少（只给本轮段）成本降，早轮残留没人回看，分低。所以这一层回答的问题只有一个：**这一轮哪些句子必须放在它们面前，凭什么。**

"凭什么"必须是可观察的信号，不是文本体积。信号有四种，每种有一个主人：

1. **本轮文本**（代码）：本轮新增和修订的句子所在的段。
2. **修订**（归属模型提出，带出处）：这句改了早轮哪句 → 那段新旧并列。出处标 `cue`（原文有线索：previously / instead of / no longer / Changes to / 作者编号）或 `inferred`。
3. **变化单元**（四种来源，各带标签）：会一起被改的句子集合。
   - `cue`：作者写明的横切——"manifest 改产 BLAKE2b 而不是 SHA256""ingest 和 transform 不再写 .sha256""verify 仍读校验文件"同轮点名四个命令；"Changes to validate / build / diff / promote"；Previous/New；F16 这类编号。
   - `revision`：一条修订把新旧两句连成一个单元。
   - `guard`：一条检查运行时读到的句子集合（观察出来的共依赖）。
   - `model`：前三种都没有时归属模型提出。
   一句可属多个单元；单元可跨命令。**对象（命令）降为标签**，不再是交付单位，对象级关系边取消。
4. **两张名单**（代码）：
   - 未结名单：轮末仍有失败检查、untouched 条目或开放项的命令。
   - 轮巡名单：曾有发现、已 ≥ 2 轮无任何条目的早轮命令，每轮 ≤ 2 个，轮转。
   名单上的命令附当前段进审查请求，各要至少一条检查。

另有一条代码可读的作者声明：**范围声明**（"没提到的行为照旧""第 1–4 轮行为继续成立"）→ 记为本轮全部守卫在力，报告列出。

这四种信号决定包的五类内容（DEEP §3.1）和审查请求的范围（DEEP §2.2）。文本体积只是结果，不再是手段。

为什么要这样而不是回到整对象视图：整对象视图在 dpipe 上能顺带做到回看，是因为 dpipe 按命令分节、横切少（26 个任务里最少）。换一份按话题写的文档（d10_w4、d12_w1），对象视图既大又抓不住横切。名单和变化单元是把"回看"和"横切"做成显式机制，各有上界，不依赖文档形状。

## 二、效果（开发按此做，顺序建议 E1 → E2 → E4 → E3 → E5）

E1 变化单元与修订出处
- 归属输出改为：每句 ≥1 对象标签；修订带出处（cue 片段原文 / inferred）；变化单元列表（成员句子、来源标签、名字）。对象级 refers_to / applies_to 边不再产生，旧记录忽略。
- cue 提取在代码里做（不进模型提示）：Changes to `X` 段、previously/instead of/no longer/now … 句中点名的命令、Previous/New 对照段、作者编号（F12、Section 21、round-3）。提取结果作为单元候选交给归属模型确认成员，不让模型重新发明。
- `guard` 来源：每条检查入库时其 units 形成或并入一个单元。
- 当前有效文本的计算不变（只依赖句子 + 修订）。

E2 范围声明
- 代码识别"未提到的行为照旧 / 第 n–m 轮行为继续成立 / remains unchanged"类句子，记为"本轮全部守卫在力"，报告列出命中的句子；不影响守卫本身的重跑。

E3 包的第 3 类改为按单元
- 本轮触及的变化单元里、落在其他命令上的句子所在段进包（取代边带入的对象头）；预算超限时先裁 `model` 来源的单元段，再裁开放项段，本轮段与修订段不裁。

E4 审查范围由两张名单决定
- 审查请求新增"未结名单""轮巡名单"两节，每个命令附当前段、附未结原因（哪条检查挂 / 哪条 untouched / 哪条开放项），要求各至少一条检查；横切单元跨 k 个命令时列出 k 个命令各要一条检查，缺的记为覆盖缺口。
- 轮巡上限每轮 2 个命令，按"距上次有条目的轮数"降序轮转。

E5 报告
- 每轮加：单元数与来源分布；修订出处分布；名单内容与由名单带来的发现数；横切单元交付到的命令数 / 涉及命令数；范围声明命中；包各类字符数。
