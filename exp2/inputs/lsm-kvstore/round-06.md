Add server-side cursors. `CURSOR_OPEN [flags]` creates a cursor backed by a snapshot taken at open time. Output: `CURSOR:<id>` where id is a monotonically increasing integer starting at 1. The cursor starts positioned *before* the first key. Flags: `--prefix <p>` restricts the cursor to keys with that prefix, `--reverse` flips the direction so CURSOR_NEXT goes backward and CURSOR_PREV goes forward.

`CURSOR_NEXT <cursor_id>` — advance one position, output `<key>\t<value>`, or `END` if exhausted. `CURSOR_PREV <cursor_id>` — move back one position, output `<key>\t<value>`, or `END` if before the first key. `CURSOR_SEEK <cursor_id> <key>` — position at the smallest key >= seek key (or largest key <= seek key if `--reverse`), output `<key>\t<value>`, or `END` if no match. After CURSOR_SEEK, CURSOR_NEXT advances from the seeked position and CURSOR_PREV returns the key *before* the seeked position. `CURSOR_CLOSE <cursor_id>` releases the cursor and its underlying snapshot. Output: `OK`.

Cursors see a consistent snapshot view — expired, deleted, and range-tombstoned keys are invisible. Merged keys (from R4) return their folded value. Invalid cursor IDs return `ERROR: invalid cursor`. `STATS` adds `open_cursors`. Cursor IDs and snapshot IDs use separate ID spaces.
