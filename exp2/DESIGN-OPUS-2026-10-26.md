# 四功能重设计（Opus，2026-10-26）

状态：设计稿，待与用户逐条讨论。未读 src/exp2 代码，模块与现状取自 NIGHT、NOTES 摘要、两份评审与证据目录；凡涉及代码现状的说法都需开发会话先审。证据等级用四档：多次一致 / 一次运行 / 只有重放 / 被推翻。

## 0. 根因与硬约束

**根因。** 现行系统只知道"哪里失败过"，不知道"哪里从没被验证过"。下面三个被推翻的部件都是这一个缺陷：
- 审查范围由失败记录决定（名单）。
- 守卫覆盖由"有检查读到这句"决定，不论检查是否通过过（K1）。
- 早轮回看靠全文顺带发生（rep1j）。

按需交付去掉全文之后，"顺带"没了，又没有东西替代，于是早轮从没被验证过的行为就无人负责。差集 rep1n/p/q 的 R3–R6 以 (i) 类为主，就是这个结果。

**硬约束：不是全文。** 定义如下：任一轮里，所有消息交给执行方和审查员的原文句子，按接收方去重后字符数 ≤ 本轮原文 × 2 + 10k。检查材料（命令、输入、输出、期望）不算原文，单独报告。

在基线上自测：
- rep1j R3–R6 包 55k/46k/50k/55k，线是 28.9k/19.5k/18.6k/16.6k，**不合格**。
- rep1k 24.8k/9.4k/14.0k/11.3k，合格。
- rep1o 38–39k，不合格，超出来自开放条目；所以这条线必须覆盖全部消息，不只覆盖包。

## 0a. 怎样保证交付的不是原文整段或全文

### 内容形态

按接收方分开，不再"三方同一份包"。

| 类 | 形态 | 进包触发 | 接收方 | 上限 |
|---|---|---|---|---|
| A 本轮原文 | 本轮新增段，带标题路径 | 每轮都进 | 执行方、审查员 | 等于本轮原文，不裁（这就是本轮任务） |
| B 修订 | 被有线索修订的早轮**句**（不是段），旧句与新句并列，带标题路径 | 本轮有该句的有线索修订 | 执行方、审查员 | 只到句；被整节取代时，旧文只进一行 earlier text（6458a9e 已如此） |
| C 条目 | 检查材料（命令、输入、现在输出、期望）+ 绑定**句**的原文 | 条目开着 | 执行方 | 同一句每轮每接收方只引一次；超限时句文降为句编号，检查材料保留 |
| D 债切片 | 验证债里被选中的**段** | 第 3 节的切片规则 | **只给审查员**；执行方只收到由它产生的失败检查（走 C） | 每轮 ≤ S 字符，S 由离线自测定（初值 8k） |
| E 守卫 | 不交付原文；只有绑在被修订句上的守卫给出命令、输入、当前输出 | 同 B | 执行方 | 不含原文 |
| F formalizer 输入 | 发现原话 + 绑定句 | 每条发现 | formalizer | 只到句 |

不进任何消息的：整对象视图、未修订早轮段、守卫清单、任何"顺带"上下文。

### 谁强制、在哪一步

代码里只有一个交付账本：每轮、每个接收方一张已送句编号表。包、审查请求、修补消息、formalizer 请求在发送前都过同一道预算检查；不允许有绕过账本的消息路径。具体放在 view.ts 还是新文件，由开发会话审后定。

**线：** 每接收方每轮原文字符 ≤ 本轮原文 × 2 + 10k（第 0 节）。

**超限时的裁剪顺序：**
- 执行方：C 的句文按条目从旧到新降为句编号；A、B 不裁。
- 审查员：D 缩小直到为 0；A、B 不裁。
- 若 A + B 本身就超线，照发，记为 `over_line: A+B`，按违反计入报告。

两个接收方各有各的预算，互不挤占：修补条目多（rep1o 型）不会挤掉审查员的切片。

**记录：** 每轮报告写明
- 每接收方各类字符数和线；
- 裁掉的项：段或句编号、类别、字符数、裁的原因；
- 是否 over_line。

### 切片会不会累积成全文

不会：每段在一个轮转周期里最多被送一次，单轮最多 S 字符。三条约束：
1. **单轮上限 S**：S 远小于全文。dpipe R6 时全文约 70k，S 初值 8k。
2. **轮转不重复**：一段进过切片后，在其余债段都轮到一次之前不再进切片。
3. **离债即出**：一段一旦有通过的检查（成为守卫），就离开债，不再被切片送出。之后由守卫在代码里守，不靠文本。

所以一次运行里，早轮原文经切片被审查员看到的总量 ≈ 债的大小 × 轮转次数。它随守卫增长而缩小，不是每轮一份全文。rep1j 是每轮约一份全文（55k 对全文 56k）。

**审查员会话：** 若会话跨轮复用，账本按会话去重：同一段在同一会话里不重发。若每轮新开会话，则单轮上限即为该会话所见原文的上限。现状是哪种，开发会话先确认。

### 离线怎么验

注意：在新规则下重算"每轮 ≤ 线"是同义反复，因为预算由代码强制。所以离线要验的是**裁剪的代价**，不是线。
1. 在 rep1j/k/n/o/p 的句子状态上，用新组装规则重算每轮各接收方各类字符，并与原记录的包字符并排。原记录：rep1j R3–R6 55k/46k/50k/55k，rep1o 38–39k。
2. 每轮被裁掉的量：C 句文降为编号的条目数，D 被缩小的字符数。rep1o 型轮次要单列。
3. 在第 2 点的预算下重做第 3 节的覆盖检验：带 (i) 类用例的命令，残留出现后 ≤ 2 轮内进入切片的比例。不到 100% 时，调 S 或轮转顺序，再验一次；S 在这一步定死后才进入真实运行。
4. 每次运行累计经切片送出的不同早轮段数，与在力早轮段总数之比，以及每段被送的次数。最大值应为 1–2，不应接近轮数。

### 真实运行每轮报什么

- 每接收方各类原文字符（A/B/C/D/F）与线、over_line。
- 裁剪清单。
- 验证债大小（段数、字符），本轮切片的段，每段结果：写了检查与否、通过与否、是否成为守卫。
- 累计送出的切片段数 / 在力早轮段数。

判定：某轮任一接收方超线且不是 A+B 所致，即为实现缺陷，算"不过"。
- 债大小在 R3 之后应不增。增长说明切片拿不到通过的检查，要看第 3 节的缺项。

## 1. 四个功能各保证什么

| 功能 | 保证（一句话）|
|---|---|
| 发现 | 每条在力的早轮要求，要么有一个在当前构建上通过的守卫，要么在有限轮内被审查员实际执行一次并留下检查。 |
| 定位 | 每条发现、检查、守卫都绑定到当前在力的句子；句子的在力状态只由句子库和有线索的修订决定。 |
| 修复 | 每条送出的条目，在一个周期内得到一个可路由的结局：修好、改了没对、没碰、或被裁定条目本身错。 |
| 守卫 | 只有在某个构建上通过过的检查才算覆盖；覆盖的行为被改坏，下一周期一定以带材料的条目回到执行方。 |

## 2. 唯一新增的事实：验证状态

**主人是代码**，由已有检查记录算出，不调用模型。每个（命令，段落）在每个构建上有三种状态之一：
- **守住**：至少一个绑定到该段的检查在当前构建上通过。
- **失败**：有绑定检查，全部失败。
- **未验证**：没有绑定检查。

另外，"失败且从未通过"单独标出，例如 K1。

未验证段 + 从未通过段 = **验证债**。它取代两张名单，作为审查范围的唯一来源。它不读官方测试，不靠模型声称，只看 IC 自己有没有拿到"这里是对的"的证据。

## 3. 发现

**事实与主人：** 发现由审查员负责（模型，可被复现反驳）；审查范围由代码按验证债决定。

**机制：**
1. **范围 = 本轮新句与被修订句 + 验证债的一个切片。**
   - 切片顺序固定：先是从未通过段所在的命令，再是未验证段，按轮次从早到晚、按命令轮转。
   - 切片字符受第 0 节预算约束。
   - 失败类：(i) 早轮没人点名。证据：差集 rep1n R3–R6 15–18 个，rep1p R5 18、R6 16，rep1q R4/R5 28/25；validate 不在任何名单上（rep1p 补查）。
2. **范围内每一段必须有一条在当前构建上执行过的检查**，通过或失败都行；或者写明"无可执行行为"并给出理由。
   - "跑过不写"算缺项，计入报告。
   - 通过的检查当场成为守卫，该段的债被清掉。
   - 失败类：引到了却不点名。证据：rep1p R5 有 3/8、R6 有 4/8 在名单上而没有条目。
3. **横切不再单设机制。** 本轮一句点名 k 个命令，就产生 k 个范围项，由规则 2 覆盖。失败类：manifest 漏看（rep1j R5，一次运行）。

**删：** 未结名单、轮巡名单、附录"Items the repairs did not settle"、全局单元、按单元带段（E3 在 dpipe 上为 0 字符）、范围声明进状态。

**验收：**
- 离线：在 rep1n、p、q 的记录上按新规则算每轮的债与切片。差集中带 (i) 类用例的命令，在残留出现后 ≤ 2 轮内进入范围的比例要达到 100%。预算 k 由这一步自测确定，不预设。
- 真实运行，同一代码跑两次：
  - R3–R6 差集 A 中 (i) 类每轮 ≤ 2。基线 rep1j 0/0/1/0、rep1k 0/0/0/2，自测可达。
  - 原文字符线（第 0 节）。
  - 缺项数只报告，不设线。

## 5. 修复

**事实与主人：**
- 结局由代码判定，用输出口径：fixed / touched / untouched。
- 执行方对条目的回答只用于路由。
- 裁决由审查员做，并由检查重跑验证。

**机制：**
1. **一种修补消息形态。** 所有条目——新发现、带入的、回归的——都以"检查材料 + 绑定句"给出，不带整段，并要求逐条回答 done / not done / disagree。现在的"untouched 单独消息"并入这一种形态，删掉单独路径。
   - 失败类：长清单里没读到。证据：修补清单 47/83 没读到，逐条作答的单独消息 0/54（执行方会话，一次读取）。
2. **同周期裁决。** 下面三种情况在下一周期之前送一次审查员裁决，不等后续审查轮：
   - 执行方答 disagree。
   - 检查从未通过且已送修过一次（K1 类）。
   - 落在推断修订句上的守卫翻转。

   审查员拿到的是句子、检查、执行方理由，裁定三选一：条目错（改写或退役）、守卫过时（退役）、维持（连同裁决重送）。
   - 失败类：有理的不同意无人裁、错误期望反复送。证据：V2.1.2、V2.1.8、V3.1.10/11、CSV 引号跨周期跨轮重复送；rep1n 送审 16/22 没被问到；G5/G7 守旧行为。
3. **答 done 但检查仍挂的**，下一周期附上现在的输出重送，不裁决。证据：说已做 27 次。
4. **"做了别的"（55 次）与"碰了没对"**（rep1p R2 51 个）不加机制：没有证据指向原因，只做度量。

**删：** 单独消息路径、二次回退送裁决、回归持续送问题通道（并入机制 2）、26% 线（已闭）、排序假设。

**验收：**
- 离线：在 rep1n/p 的记录上重放路由。39 条拒绝中的 disagree 100% 在同周期进入裁决；V2.1.2 这类重复送出的条目，在新规则下重复送的次数为 0。
- 真实运行，同一代码跑两次：
  - R1 闭合率 ≥ 52%，R2 ≥ 81%（独立评审第二轮 1(a)，基线自测可达）。
  - 线不过时按 (i)–(iv) 分账报告。
  - 裁决数与"条目错"的比例只报告。

## 6. 守卫

**保留：** 出生、每周期重跑、按有线索修订分类翻转、改过即过期、守卫核算（多次一致）、回归变成带材料的条目而不整周期回退（批 5 A/B）。

**改：覆盖只按通过过的检查计。**
- 从未通过的检查不算覆盖，它所在的段计入验证债，由第 3 节进入审查。
- 第 3 节规则 2 让早轮段尽早拿到一个通过的检查，因而尽早得到守卫。
- 失败类：覆盖名义上有、实际没有。证据：R1 ingest 的 13 句只在 K1 里，K1 历次运行都失败；rep1p R6 改坏 8 个 ingest 用例无人守。

**验收：**
- 离线：报告各运行"名义覆盖"与"通过覆盖"两个比例的差。
- 真实运行：轮内改坏（首次交付通过、轮末失败）的用例中有守卫的比例；基线先在 rep1j/k 上算出，再定线。

## 8. 实施顺序

**起点代码：rep1k 线**，即包改造 + 6458a9e + 批 2 + 批 3(c)(b) + 路径修复。不带批 3a、4、5：它们有真实运行结果，判"不过"或被推翻。批 5 的 A/B 作为第 6 节的保留项，跟第一批一起进，同属守卫的处置。这一点需用户确认。

每批两次运行，与 rep1j、rep1j3、对照两次并排。

1. **第一批 = 验证状态 + 发现（第 2、3 节）+ 守卫的通过覆盖（第 6 节）。** 先做它的理由：
   - (i) 类是 R3 起三次运行的最大丢分类。
   - 它是按需交付不退化为全文的前提：没有它，唯一能回看早轮的办法就是全文。
   - 守卫覆盖与它共用同一个事实，拆开做会做两次。
2. **第二批 = 修复（第 5 节）+ 定位的一处改动（第 4 节）。** R2 的 (ii)/(iv) 是这批的对象；它依赖第一批产出的通过检查作材料。
3. **第三批（条件）= formalizer 并入。**

### 10.2 补法

每条：一种机制、一个主人、对应的失败类、离线验收、真实运行验收。没有证据的写"不补，只度量"。

- **G1：债按句记，交付仍按段。**
  - 主人：代码。一句算"守住"，当且仅当有一条通过的检查在其 units 里引用了这句。切片仍以段为单位送出，提供上下文。
  - 失败类：段内未验证行为被掩盖（rep1n window 11）。
  - 离线：在 rep1n R2–R6 的状态上数 window 段内被通过检查引用的句数与总句数。若未引用句不是 0，说明按句记能把 window 留在债里；这个量决定第一批采用按句还是按段，**做第一批之前先测**。
  - 真实：差集 (i) 类线（第 3 节）。
- **G2：允许审查员声明"非行为句"，离债。**
  - 主人：审查员声明，代码记录。第 3 节规则 2 的"无可执行行为 + 理由"即是这一声明。被声明的句离开债；该句之后被有线索修订，或被任一发现引用时，回到债。
  - 失败类：推断，但不补的话切片会被堵住，所以要补。
  - 离线：在 rep1n/p/q 的 R6 状态上算债的大小，人工抽 20 句估非行为句的比例。
  - 真实：每轮声明数，以及声明后又回到债的句数，只报告。
- **G3：债只含"无通过检查且无开着条目"的句子。**
  - 主人：代码。开着条目的句子归修补回路；条目被裁为"条目错"而退役时，句子回到债。一个事实只有一个主人。
  - 失败类：推断（定义重叠）。
  - 离线：重放中，同一句同时出现在切片和条目里的次数为 0。
  - 真实：同一个数。
- **G4：不补，只度量。**
  - 理由：判断检查是否"弱于发现"要靠模型，再加一道判断会加重。G1 按句记已经能缩小弱检查的覆盖面：弱检查只引用它真正测到的句，前提是 formalizer 引用如实。
  - 离线：在有官方失败的 requirement_ref 上，算其句子被通过检查引用的比例，作为"假守住"的上界。每次运行报告。
  - 若第三批 formalizer 并入审查员，这个问题与 G5 一并重议。
- **G5：从未通过的检查送修一次后自动进裁决，不等执行方 disagree。** 这就是第 5 节规则 2 的第二种情况，补法已有，这里只是明确它也覆盖 G5。
  - 离线：在 rep1n/p 上，V2.1.2 这类条目在新规则下最迟第 2 周期进裁决。
  - 真实：报告裁决里"条目错"的数量。
- **G6：代码检测振荡，自动送裁决。**
  - 主人：代码检测，审查员裁决。同一条目与同一守卫在相邻两个周期交替失败（修 X 坏 G，再修 G 坏 X），就把"条目 X 与守卫 G 冲突"送同周期裁决，不需要执行方开口。
  - 失败类：反复打破同一守卫（rep1o 8/14），以及守卫守旧行为（G57）。
  - 离线：在 rep1j R5 与 rep1o 的周期记录上重放，振荡在第二次交替时被送裁。
  - 真实：振荡次数、裁决结果。
- **G7：每条目每轮最多裁一次。**
  - 主人：代码。裁"维持"后再 disagree，就带裁决原文带入下一轮，并计数，不再裁。
  - 失败类：推断（防止循环）。
  - 离线：重放中每条目每轮裁决次数 ≤ 1。
  - 真实：同一个数。
- **G8：不补，只度量。** 每次运行后离线核对：被裁"条目错 / 守卫过时"的条目，其 requirement_ref 在官方测试的结果，作为裁错率的上界。运行中不用官方数据。
- **G9：漏答的条目视同没读到。**
  - 主人：代码。漏答的条目下一周期放在消息最前面重送；连续两个周期漏答，就按"检查从未通过"进裁决。
  - 失败类：长清单里没读到（47/83）。
  - 离线：重放中漏答条目 100% 进入下一周期。
  - 真实：漏答率，与修补清单的 47/83 对比。
- **G10：不补，只度量。** 现有证据没有指向原因。分账 (iv) 与"做了别的"每轮报告。第二批跑完后若这两类仍是最大类，再读这些周期的执行方会话，原因找到之前不加机制。
- **G11：轮转指针只在段被实际送出后才前进。**
  - 主人：代码。被裁的段留在队首，下一轮优先。
  - 失败类：推断。
  - 离线：重放中，任一债段从进入债到第一次被送出的轮数最大值不超过 3；超过就调 S。
  - 真实：同一个数。
- **G12：时间进入成本线。**
  - 主人：代码。每轮报告墙钟时间，并把三次审查、formalizer、裁决、执行方各自的用时拆开。
  - 线：沿用用户 10-23 的 ≤ 对照 2 倍。基线需先从 rep1j 与对照的运行目录算出，确认这条线在基线上可达；不可达就请用户重定，不由我改。
  - 这一条是机械改动，随第一批一起做。
- **G13：不补，只度量。** 每次运行抽查切片段的归属。

### 10.3 修订后的实施顺序

起点不变：rep1k 线 + 批 5 A/B。每个行为批次单独做，每批两次真实运行，与 rep1j、rep1j3 和对照两次并排。

   - G12 的基线时间。

   这三个数决定第一批的参数，不改代码。

   - 验证状态改为按句记（G1，以测量结果为准）。
