## 1. [mech] 单位要点到句：照常准入，只计数，作非阻断提示（Opus 决定 B）

做法：
- 一个检查或审查条目的单位如果是节，或是含句子的段，按严格口径不覆盖其中任何句子；严格口径由验证状态（第 3 个提交）落地，准入不变。
- 判定在 `coarseUnit`（checks.ts），只看注册表层级：节一律算粗；段有句子子块才算粗；没有句子的段（例如只有一个列表的段）不算粗。
- 写检查：`blocks` 的 schema 描述和提示要求写句子、列表项或从句的编号（`COARSE_HINT`，一句话两处共用）。`checkChecks` 不再因粒度报问题。`coarseHints` 列出草稿里的粗单位；这些提示只在本来就要发出的修补请求里随附，并注明"不阻断"，不会为它单独多发一次调用。
- formalizer：粗单位保留在条目里，不算问题；提示同样只随本来要发的第二次请求附上。每次调用记录 `coarse_units`。
- 报告：写检查一行加"units coarser than a sentence N in M checks (admitted, they cover no sentence)"。数据来自 `checkWritingCounts`，按本轮进入的检查计。

依据的运行：

## 2. [behav] 不撤回修复：回归作为带材料的条目带入，分开计数（5A(a) + 5B 测试）

做法：
- 修补把一个原先通过的守卫在本轮未动的文本上弄挂，这个修补不撤回，树不回退，同一周期新生的守卫照常出生、编号连续。
- 回归按原有路径变成条目：`renderGuardItem` 给出守卫编号、所依据的原文、命令和输入文件、程序现在的输出与期望，和本周期其他条目一起发给执行方。修补消息不再带 "reverted by the controller" 的说明，被这次修补修好的条目也不再重发。
- 回归持续不消失：不送裁决（决定 ①）。同一输出下由 `sends.plan` 按原规则暂缓；轮末仍然失败的守卫进 `final`，带材料带入下一轮。
- 计数：`accept.regressions = { raised, fixed_next, persisted }`。raised 是本轮在未改动文本上的翻转数；在下一个周期复查时，守卫通过计 fixed_next，仍然失败计 persisted。报告 Guards 一行加 "regressions raised …, fixed on the next cycle …, still failing then … (no repair is reverted)"。
- 删掉的：撤回分支、被撤回周期的守卫编号回收、撤回后重发条目和说明。`reverted` 字段保留，恒为 0，供与旧运行对比。
- 测试：batch-1、block-accept、revert-ids-replay 里预期撤回的四条改为预期不撤回、回归带材料、计数正确；5B 的四要素测试（batch5.test.ts，原 a023228）原样移入。

依据的运行：revert-cost（rep1o-2026-10-25/revert-cost.json，24 次撤回）：被撤回的程序里已经修好、因撤回而丢掉的条目，rep1j 5 次丢 25 条，rep1n 4 次丢 8 条，rep1o 14 次丢 183 条，rep1j3 1 次丢 6 条，合计 222 条，占送出的 571 条的 39%。

已知风险（决定 ② 的说明）：本批里，一个守卫如果本身是错的（守着旧行为），只有在有线索的修订让它过期时才会退出。执行方每次照条目把它改回去，都会挂在另一个条目上，这种来回要等第二批的裁决和振荡检测处理。

验收数字（逐文件重跑，主机拦截时重试）：batch5 1/1，batch-1 11/11，block-accept 18/18，revert-ids-replay 1/1，g77-replay 5/5，block-accept-fix 24/24，replay-baseline 1/1（七个 R1）。batch-4 的 docker 测试有一次失败：那次各周期的试运行都被主机拦截；单独重跑在 529d983 和本提交上都通过。全量测试：984 条，973 通过，10 条失败即已知 10 条（spawn UNKNOWN 1 次）。

离线成立：没有一个周期被撤回；回归在下一次修补消息里带着四要素出现，被这次修补修好的条目不会再发；守卫编号连续；回归的三个计数在测试场景里正确（raised 1、fixed_next 1、persisted 0）。
离线做不到的：执行方收到带材料的回归后，是一个周期内修好，还是在两个条目之间来回；上面已知风险里的错守卫（守旧行为）会造成多少次来回。离线只有桩执行方。
真实运行要看的线：每轮 regressions raised / fixed_next / persisted；persisted 的守卫是否在下一轮被修好；与旧运行的撤回丢失数（222/571）对比，丢失为 0；R5/R6 ≥ 656/688，R3–R6 (i) 类每轮 ≤ 4。

## 4. [behav] 交付账本，按接收方分包（第 0a 节，决定 3、4）

做法（新文件 src/exp2/delivery.ts；view.ts、accept.ts、review.ts、serial.ts 接入）：
- 账本：每轮一本。按接收方（执行方、审查员、formalizer）记本轮给出的原文块及其字符，分类为 A（本轮段）、B（被修订的早轮句）、C（条目所依据的原文）、D（债切片，第 5 个提交）、F（formalizer 读的）。同一块对同一接收方每轮只计一次；已给出的块或其中的单位再次引用时只写编号（"… (given above)"）。线 = 本轮原文 × 2 + 10k。
- 包（`roundPackage(…, { delivery: true })`）：
  - 边带来的段删掉（决定 3），包括 applies_to 源被修订时带来的整对象。边的条数照记。
  - 被修订的早轮单位只给其旧文一行（"earlier text of <id>: …"），不再给它所在段的在力全文（B 到句）；在力的新文就是本轮的 A。
  - 开着的条目不再以段进包。
  - 比较项（守着被修订单位的守卫）只写所依据的单位编号和现在的编号，不引原文（E 类）。
- 执行方：工作单的包 = A + B；带入的条目 = C。
  - 守卫回归：守卫编号、依据句、命令和文件、输出与期望。
  - 审查条目：审查员原话、依据句、命令和文件、输出与期望（新加的 `renderOpenItem`；此前只有审查员原话，依据段在包里）。
  - A + B + C 超线时，从最旧的条目起把依据句降为编号，记入裁剪清单。
  - 轮内修补消息里的回归条目同样经账本引用：已给过的句写编号，超线写编号。
- 审查员：包 = A + B（第 5 个提交加 D）。带入的条目以"条目编号、依据单位编号、命令和文件、输出与期望"列在审查请求末尾的 "Items still open from earlier rounds" 一节，不带原文（此前审查员没有这份清单，但有条目所在段）。守卫翻转问题里引用的旧文 / 新文，已给过的写编号。
- formalizer：读审查员同一份正文，记为 F，在线外（决定 4）。
- 线外角色：归属和写检查本轮各次调用请求里 sources 的字符记入账本，超线标出（决定 4）。
- 报告新增一行："Original text delivered: line …; executor …(A, B, C); reviewer …(A, B, D); formalizer …(outside the line); cut to ids …; read outside the line: attribution …, check writing …"。完整数据在 report.json 的 delivery 字段。
- 测试：delivery.test.ts 5 条；block-accept 的串行报告测试加了交付、验证状态和用时三行的断言。

依据：第 0 节的硬约束（rep1j R3–R6 包 55k/46k/50k/55k，超线；rep1o 38–39k，超出部分来自开着的条目）；决定 3、4。

验收数字：delivery 5/5，chain 15/15，neutral 3/3（D 段的标签改为 "earlier, no passing check rests on it yet"，避开中性词表里的 VERIFIED），batch-1 11/11，block-accept-fix 24/24，batch5 1/1，verification 5/5，replay-baseline 通过，g77-replay 5/5，revert-ids-replay 1/1。block-accept 和全量测试见报告。

## 5. [behav] 审查范围的债切片（D）、轮转指针、NOT BEHAVIOUR 声明

做法（新文件 src/exp2/slice.ts；review.ts、accept.ts、verification.ts、serial.ts、report.ts 接入）：
- 切片由代码按轮初的验证状态选，只给审查员（formalizer 读同一份正文，记为 F）。
- 候选：早于本轮、在债里的句所在的段（G3：开着条目的句不在债里，所以不会同时出现在切片和条目里）。
- 顺序：
  1. 上一轮的缺项所在段（第 6 个提交起填）；
  2. 上一轮因字符不够被裁的段；
  3. 有从未通过检查的段（K1 类）；
  4. 其余按轮次从早到晚，同一轮内按命令（对象）轮流各取一段，每个命令内按文档顺序。
- 轮转（G11）：一段送出后，在其余债段都轮到一次之前不再进切片；全部轮到后从头开始。指针只为实际送出的段前进；被裁的段不进轮转，下一轮排在队首。
- 上限：每轮 ≤ 8 段，且 ≤ 审查员的线 − A − B（`delivery.room("reviewer")`）。放不下的段记入 cut。
- 送出形态：段的在力全文，带标题路径，标签 "earlier, no passing check rests on it yet"，记为 D。
- NOT BEHAVIOUR（G2，规则之外的余量）：
  - 审查请求在交付模式下加一节说明：可写 `NOT BEHAVIOUR <句 id>: <理由>`。
  - 代码只收在力的句（从句按其所在句），每句一次，记在 `accept.declared`。
  - 此后同一轮或更晚有审查条目引用这句，声明作废，句回到债。
  - 这类行和 SUPERSEDED 一样是控制行（`CONTROL_LINE`），不算偏差条目；只有控制行加 NO ISSUES 的回复算无问题。
- 记录与报告：`execution.slice`（送出、被裁、轮转、预算、轮初债），报告新增一行 "Debt slice: …"。
- 测试：slice.test.ts 6 条。
