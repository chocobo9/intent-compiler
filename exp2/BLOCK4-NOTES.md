# 实验 2 第 4 块：传播

分支 `exp2-block1`。代码在 `src/exp2/checks.ts`、`src/exp2/workorder.ts`、`src/exp2/store.ts`，测试在 `test/exp2/propagation.test.ts`。没有改 `src/core/`，没有调用模型。

## 1. 做了什么

1. **依据精确到子句**（4.4）：一条检查的依据单元改为两部分：
   - 它引用的块；
   - 每条逐字期望在所引块里所在的最细单元，即完整包含引文的那一层，可能是子句、单元或段落（`quoteUnit`）。

   部分修订只让依据与被改单元重叠的检查过期。检查自己引用了较粗的块时，按它引用的粒度判断，这一点不变。
2. **refers_to 让检查过期**（4.3）：检查的依据单元如果与某条 refers_to 边的引用方重叠，被引用的块在检查入库之后被替代或修改时，检查标为过期，原因记为 `cause: { kind: "refers_to", source: 被引用块 }`。被引用的对象本身不产生改动。
3. **共享约定修订后按 uses 重推导**（4.5）：
   - 检查的 uses 里的对象在检查入库之后有改动记录，检查就标为过期（`cause: convention`）。
   - 推导请求的 `stale` 现在列出本轮所有过期的检查，不再只列本轮范围里的对象。入库核对允许为这些检查的对象写新检查，即使对象本轮没有改动；其他对象仍然退回（`object_not_in_scope`）。这样模型只重推导这一批。
   - 工单任务区里，这些对象带 `why: "convention"`，并在"受约定修订影响"一项里列出是哪个约定、哪些检查要重推导。
4. **applies_to 让目标对象进入本轮范围**：这条在第 1 块评审后已实现（改动记录的 `applied`），这次补了测试：目标对象只靠 applies_to 进入范围的情况。
5. 所有过期和退役事件现在都带 `cause`，取值为 `basis`、`refers_to`、`convention`、`suspect`、`proposal` 之一。

## 2. 离线验证结果

用真实的 R1–R15 原文和第 1 块的归属替身建好登记，再手工构造检查库条目。exp2 共 88 项，全部通过；全量 776 项，769 通过，失败的 1 项仍是原有的 `repair-batch`。

- **refers_to**：R7 的"The `manifest` command scans a directory"（`R7.S1.P2`）引用 `R1.S5.P2`，R10 部分修订了 `R1.S5.P2`。
  - 依据 `R7.S1.P2` 的 lineage 检查：R9 时不过期，R10 时过期，原因是"R7.S1.P2 refers to R1.S5.P2, partly revised in round 10"。
  - 依据 `R7.S1.P3` 的检查：不受影响。
- **约定**：R5 修订了 transform。
  - uses 里有 transform 的 filter 检查过期，原因是约定；
  - 不标 uses 的 filter 检查、sort 检查都不受影响；
  - 推导请求的 `stale` 只有那一条；
  - 入库核对接受 filter 的新检查（filter 本轮没有改动），退回为 sort 写的检查；
  - 工单里 filter 在任务区，原因 `convention`，并写明哪个约定、要重推导哪条检查。
- **applies_to 单独起作用**：把 R5 的归属替身改成 transform 本轮没有自己的块，也没有被覆盖的旧文。transform 的改动记录里 entries 和 received 都为空，类型只有 `applies_to`，它仍进入本轮范围和工单任务区。
- **精确到子句**：
  - R5 只撤回 transform 结尾项的第三个子句。逐字期望引用第二个子句（"write the result CSV to `<output>`"）的检查不过期，引用第三个子句的过期。
  - R15 改了 R13 的第 4 步和 32 字符那一项。依据第 1 步（`s5`）和引用第 2 步原文的检查不过期，依据或引用第 4 步的过期。

## 3. 需要设计会话决定的问题

**3.1 约定的任何改动都让使用它的检查过期。** 包括"新增"类改动。新增的规则也可能让旧期望不再完整，所以宁可过期，重推导一次。如果只想在修订、部分修订、撤回时才让检查过期，`staleChecks` 里加一个类型过滤即可。

**3.2 什么是"共享约定"，由 uses 决定。** 设计说不预先声明对象类型。这里任何被某条检查列进 uses 的对象，在传播时都按约定处理。例如 filter 的检查通过 transform 命令运行，把 transform 列进 uses，transform 的修订就会让它过期。

**3.3 检查引用粗块时，过期也粗。** 例如 R1 的 verify 检查引用了整节 `R1.S4`，R5 改了其中一项，整条检查就过期。要精确，靠模型引用细的块或写逐字引文。代码不替模型把粗块收窄，因为那需要理解。

**3.4 refers_to 只在一层上传播。** 检查依据的块引用了被修订的块，检查过期；被引用的块又引用别的块，不再往下追。原文里还没见到需要多层的情况。

**3.5 refers_to 本身不让被引用的对象进入工单。** 设计写的是被引用的块修订时，"在工单里附上被引用的原文"。原文区本来就有全部原文，工单的 `edges` 也列出了任务对象的边；没有在任务区另外复制被引用的原文，以免原文出现两次。
