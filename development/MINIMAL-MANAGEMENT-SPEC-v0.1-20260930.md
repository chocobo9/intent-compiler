# 管理层规范 v0.1：保留 IR，收缩"模型视图"（2026-09-30）

> v0 的错：把"账本太贵"错误地推成"不要 IR"。反馈：问题不在 IR 存在，
> 而在于模型**每次调用都读到全部内容**（合同、全量历史、整个 IR/计划/台账混在一起），
> 而实际每次操作只需要其中一片；更新也应该是后续操作里的增量，而不是整份重发。
> v0.1 把"系统状态"和"本轮模型视图"分开。v0 原文见 MINIMAL-MANAGEMENT-SPEC-20260930.md。

## 0. 两条原则

1. **状态与视图分离**：IR、计划、台账、产物是系统状态，完整持久、可审计，但**不整份进入请求**。
   每次调用只给"这次操作需要的那一片"＋一份紧凑清单（可见性），其余按需补取。
2. **读取按需、写回增量**：读什么由操作类型和引用关系决定；写了什么只回传被触及对象的差量，
   不再"整候选重发、整批拒绝、整批重生成"。

## 1. 系统状态（由代码拥有，持久、不进请求）

- 事件日志（用户原文、回传、能力变更；id/顺序/摘要）。
- **IR**：task / content / binding / output；id 与 revision 由代码维护；
  文本仍只来自用户原文（逐字），但**不要求逐段账目**（见 §5）。
- **Compiled plan**：atoms + relations（可执行单元与依赖），内容由模型在操作里给出。
- 执行台账：execution/dispatch 生命周期、授权 allow/deny、停止/撤销。
- 产物登记：path、代码计算的 digest、状态（可用/被替换/被撤销）。
- 审计：每次调用的操作类型、视图切片、补取请求、输出 delta、耗时与 token。

IR 保留的理由：它是"系统当前怎么理解任务"的可审计载体，也是跨轮复用的依据；
它不该消失，只该**不再默认全量出现在模型眼前**。

## 2. 视图（每次调用，按操作裁剪，有界）

### 2.1 操作类型（一次调用只做一件）

| 操作 | 目的 | 读 | 写 |
| --- | --- | --- | --- |
| `update_ir` | 把本轮委托登记进 IR（新建/修订/撤回对象） | 本轮原文 + 命中的 IR 切片 + 清单 | IR delta |
| `compile_plan` | 生成/修订可执行计划与 instruction | 相关 IR 切片（该 task 的 items）+ 清单 + 产物清单 | plan delta（atoms/relations/instruction） |
| `assess_return` | 评估执行回传、决定继续/停止/复用 | 回传摘要 + 对应 atom/完成条件 + 清单 | 评估 + decisions（+必要时 plan delta） |
| `clarify` | 需要用户决定时提问 | 缺口相关切片 | questions |

每轮调用次数：`update_ir` 必有；`compile_plan` 在前者改动了相关对象时跟进；
`assess_return` 随回传。**不再有"两级整生成"**（见 §5）。

### 2.2 每次调用的输入（固定形状）

1. **操作声明**：本次只做哪一个操作（一句话）；
2. **本轮/本次事件**：原文逐字（或回传摘要）；
3. **命中切片**：由代码按规则机械选出并展开的对象：
   a. 本轮文本点名的 id / 路径 / 输出名；
   b. 最近一次修订过的对象（revision 变化）；
   c. 状态为 pending / executing / unresolved 且影响范围与本轮相交的对象；
   d. 模型上一次调用点名的补取对象（≤K 个，代码执行并记录）；
4. **清单（manifest）**：**全部**对象的 id + 一行摘要 + revision + 状态。
   保证"可见性 ≠ 读取量"：模型知道存在什么，但只有命中/点名的才展开原文；
5. **协议切片**：只给该操作的契约（见 §4），不再给整份 51KB 合同；
6. **预算**：本次调用的 token/时间上限。

### 2.3 补取（按需）

- 模型可在输出里带 `need: [{ "item": "r-ingest@2" | "turn:7", "why": "..." }]`；
- 代码执行补取并在**同一次操作内**补足重发一次（≤1 次补取/调用，≤K 条/次）；
- 补取请求全部进审计：能观察"模型每次真正需要什么"，为后续裁剪提供数据。

## 3. 写回（增量）

- 输出 = 本次操作触及对象的 delta：
  `{ "ir_delta": [create/revise/retire …], "plan_delta": { atoms, relations, instruction }, "decisions": …, "note": …, "questions": …, "need": … }`；
- **未触及对象不回传**；每个 revise 带 `expected_revision`；
- 代码校验 revision/身份/权限，计算 digest，落库并记录；冲突时返回"只针对该对象的差量修复请求"，
  **不是整批重来**；
- 失败语义：只重试失败的那个操作；连续失败则把缺口记为该对象的未决状态并提问，
  不再有"整批失败 = 整轮无派发"。

## 4. 协议切片（每个操作一份，全部 ≤2KB，合计 ≤6KB）

- `update_ir`：字段形状 + 两条硬要求（① IR 文本逐字来自用户原文；② 未触及对象不得改写）；
- `compile_plan`：atom/relation/instruction/completion/return_when/permissions 的形状与职责；
- `assess_return`：评估字段与"回传不等于成功"的判据；
- 公共：id/revision/摘要由代码拥有；模型不得自造 id/digest。

没有 176 条散文条款、没有 18KB 示例候选；示例最多留最小骨架。

## 5. 与现状的差别

| 机制 | 现状（v2） | v0.1 |
| --- | --- | --- |
| IR / 计划 / 台账 | 每次调用全量塞进请求 | 只在系统里；按操作切片 + 清单 + 补取 |
| 合同 | 51KB 整份，每调用重发 | 每操作 ≤2KB，位置稳定（缓存友好） |
| 响应 schema | 27KB | 每操作小 schema（≤2KB） |
| 生成 | 两级整生成（IR→CI）+ 整候选重发 | 单操作 delta；未触及对象不回传 |
| 独立核对 | 全量输入 + findings 当硬门 | 按操作可选定点核对；findings **建议性**，进记录与下一轮输入 |
| 失败 | 整批拒绝、预算耗尽、整轮无派发 | 只重试失败操作；缺口记入对象状态并提问 |
| 逐段来源账目 | 强制 | 不要求；保留一条硬规则：IR 文本逐字来自用户原文（提交时检查） |
| 示例候选 | 18KB/调用 | 最小骨架（或仅 schema） |

成本目标：**每轮 1–3 次调用；单次视图典型 ≤30KB；协议 ≤6KB；schema ≤2KB；
不再随轮数线性增长**（历史与远端对象按需补取）。
对照现状：第 1 轮 105KB（合同占 50%）、后期 477KB、每次 27KB schema、每批 6–8 次调用。

## 6. 机械检查（只判形状，作用域 = 本次 delta）

1. schema 合法；2. revise 的 id 存在且 revision 匹配；3. 引用只允许指向清单中存在的 id；
4. permissions 的 operation ∈ 宿主能力、path 在 workspace 内；5. note ≤4KB。

不再有：逐段来源覆盖、goal_refs/digest 组装、parent_basis 循环、整候选覆盖率。

## 7. 怎么比（预注册，三臂 + 指标）

- 三臂：`raw`（裸）/ `current`（v2）/ `scoped`（本规范），同样 1..6 轮 dpipe、同模型、同 verifier；
- 主判据：逐轮 reward 与累计用例；
- 成本判据：每轮管理调用数、每次调用字节与 input tokens、cache_read/input、补取次数；
- 质量判据：被拒绝的 delta 数（应远低于现状的 67–90%）、整轮无派发的轮数；
- claim 夹具（dpipe 覆盖不到，必须另做）：权限撤销、修订（撤回上一条）、复用（旧产物仍可用时不重做）、
  以及"越过验收面"（裸臂 R1 的实测：题面写了 `go build -o dpipe ./...` from `/app/`，裸臂仍建到 /tmp）。
- 失败判据：`scoped ≈ raw` 且夹具上无优势 → 停止；有优势 → 逐项验证结构化能力是否值得保留。

## 8. 已知风险

- **切片选择**：视图裁剪后模型可能看不到本来相关的对象。兜底：清单列全量（可见性）、
  引用规则机械命中、模型可补取、核对（建议性）可点名漏项、审计记录补取行为；
- **模型可能少看**：用补取记录与轮次分数测量，而不是靠更多规则预防；
- 不承诺语义完整；把错误变成"可测量、便宜、可迭代"的差量修复。
