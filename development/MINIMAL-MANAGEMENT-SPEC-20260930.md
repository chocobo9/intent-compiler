# 最小管理层规范（v0 草案，2026-09-30）

> 已被 v0.1 取代（2026-09-30，用户反馈）：问题不是"IR 存在"，而是"每次调用全量读、混合读"。
> 保留本文作为迭代记录；当前版本见 MINIMAL-MANAGEMENT-SPEC-v0.1-20260930.md。

> 目的：给"管理层到底该做什么"一个可以被读、被反驳、被实现的最小定义。
> 它不是对现行 v2 的修补；它是用于对照实验的第二条实现路径（第三臂）。

## 0. 本层只回答四个问题

1. **现在要做什么**：本轮委托的完整含义（含用户固定的接口、字面量、公式、例外）。
2. **允许做什么**：操作 × 对象/路径；哪些已撤销。
3. **什么可以复用**：哪些已登记结果仍满足当前要求，可不必重做。
4. **哪里需要用户决定**：缺信息或存在真实分歧时，提出具体问题。

除这四个问题以外的任何机制都不属于本层。

## 1. 一次管理调用的输入（固定、有界）

| 记号 | 内容 | 上限 |
| --- | --- | --- |
| T | 本轮用户原文，逐字 | 不截断 |
| N | 上一轮的意图笔记（模型自撰、代码保管） | ≤ 4KB |
| R | 自上次调用以来的执行回传摘要：状态、产物清单（id + 摘要 + 代码算的 digest）、失败原因；不含完整 transcript | ≤ 8KB |
| C | 宿主能力事实：可用操作、workspace 根、点名路径的存在/可读 | ≤ 2KB |
| Q | 上一轮未决问题 | ≤ 2KB |
| P | 固定协议文本：字段职责 + 两条硬要求（见 §3），**不含示例答案、不含规则清单** | ≤ 6KB |
| 补取 | 模型可请求最多 2 条历史轮的原文（按 turn_id），一次补取、同一调用内完成 | ≤ 40KB |

典型请求 ≈ T + N + R + C + Q + P ≈ 20–40KB；不随轮数线性增长（历史只在被点名时补取）。

## 2. 一次管理调用的输出（小 schema）

```json
{
  "instruction": "自足的执行说明；执行器只读这一段",
  "inputs": [{ "artifact": "a3", "use": "作为 X 的输入" }],
  "outputs": [{ "id": "o1", "deliverable": "…", "format": "text|json|artifact" }],
  "completion": ["可观察的成功条件与所需证据"],
  "return_when": ["成功 / 失败 / 阻塞的交回条件"],
  "permissions": {
    "allow": [{ "operation": "write", "path": "src/export" }],
    "deny": [{ "operation": "bash", "path": "deploy/" }]
  },
  "note": "更新后的意图笔记（≤4KB）：当前目标、仍然有效的要求、已撤回项、产物指针、未决问题",
  "decisions": {
    "continue": ["exec-7"],
    "stop": [{ "execution": "exec-6", "reason": "用户撤回了该工作的授权" }],
    "reuse": [{ "artifact": "a3", "for": "o1" }]
  },
  "questions": []
}
```

**没有**：IR 树、content item、coverage、source 账目、revision/digest（模型不得填写）、atom/relation 图、parent_basis、checks 数组。

## 3. 谁拥有什么

**代码拥有（不可由模型代替）**

- 事件日志、turn/execution/dispatch 身份与生命周期；
- 工具边界的 allow/deny 判定（operation × path），stop 立即生效；
- 产物登记与 digest（执行器声明路径，宿主计算）；
- 意图笔记的版本化保存（按轮追加，可审计）；
- 每轮调用的输入、输出、耗时、token 记录。

**模型拥有（语义责任）**

- `instruction` 的内容：自足、完整；用户固定的细节要逐字带入（T 就在输入里，不要凭记忆重写）；
- `note` 的内容：让**下一次调用**能独立读懂当前意图；
- `decisions`、`questions`。

**两条硬要求**（写进 P，只此两条）：

1. `instruction` 必须自足：执行器拿不到 T、看不到历史；用户已固定的接口/字面量/公式/例外必须完整出现在其中；
2. `note` 必须自足：下一次管理调用只靠它就应理解当前意图；更早的细节用 `turn_id`/`artifact` 指针代替原文。

## 4. 每轮流程

```
用户输入 T
  → 组装输入 → 1 次管理调用（transport 失败重试 1 次；仍失败则本轮不派发，事件留在待办）
  → 代码校验（§5）→ 登记 execution、按 permissions 放行
  → 执行器运行（只收到 instruction + inputs 说明）
  → 回传（状态 + 产物）→ 代码登记产物/digest
  → 下一轮把回传摘要进入 R
```

## 5. 机械检查（全部便宜、只判形状）

1. JSON 符合 schema；
2. `instruction` 非空；`note` ≤ 4KB；
3. `decisions` 引用的 execution / artifact id 存在且归属本轮任务；
4. `permissions` 的 operation ∈ 宿主能力清单，path 在 workspace 内；
5. 允许"只提问不派发"（`questions` 非空且 instruction 为空），其余情况必须给出 instruction。

没有逐段来源账目、没有引用/版本/digest 校验、没有语义门。可选核对（若启用）只写 findings 到记录，并作为下一轮的**建议性**输入，不决定批次生死。

## 6. 与现状的差别

**删掉**：IR content/coverage、requirement-flow 绑定、两级生成（IR→CI）、独立核对硬门、51KB 合同与 18KB 示例、批次预算/重试/缺口携带机械、atom/relation 图与状态台账。

**保留**：事件日志、身份与生命周期、工具级授权、产物登记与 digest、审计、按需取原文。

**成本目标**：每轮 1 次管理调用；协议 ≤6KB（现状 51KB）；response schema ≤2KB（现状 27KB）；典型输入 ≤40KB（现状 105–477KB）。

**规模预估**：新增 ~600–900 行（一个单调用层 + 小 store + 协议/ schema + 第三臂接线），复用 execution-state / observer / 适配器 / 产物 digest。

## 7. 与谁比、怎么比（预注册）

- 三臂：`raw`（已有）/ `minimal`（本规范）/ `current`（v2）。
- 同样的 1..6 轮 dpipe、同模型、同 verifier。
- 主判据：逐轮 reward 与累计用例数；成本判据：管理调用数、input tokens。
- Claim 夹具（必须另做，dpipe 覆盖不到）：权限撤销（"不要再读 X"）、修订（"撤销上一条，改成 Y"）、复用（旧产物仍可用时不重做）。
- 失败判据：`minimal ≈ raw` 且夹具上无任何优势 → 本层在这些任务族上没有价值，停止；若夹具上显出优势 → 再逐项验证结构化能力是否值得加回（每次加一项、一次对照）。

## 8. 已知风险与刻意不做

- **风险**：`instruction` 可能丢细节（这正是现行 coverage 机制想防的）。本层的处理是"T 就在输入里 + 两条硬要求 + 核对记录 + 用轮次分数测量"，先测量再决定是否加机制。
- **不做多原子计划与关系门控**：dpipe 实测每轮只派发一个原子、0–5 条关系，从未作为收益被验证；需要时再按 §7 的方式加回。
- **不做跨轮结构化账本**：note 是纯文本、有上限；结构化只在"代码必须机械执行"的地方出现（权限、身份、产物）。
- **不承诺语义完整**：本层把语义错误变成"可测量、便宜、可迭代"的错误，而不是整批失败。
